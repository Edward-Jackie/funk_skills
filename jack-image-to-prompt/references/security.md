# 密钥处理规范

用户会把上游 API Key 填进工具或贴进对话。这几条是硬约束。

## 铁律

1. **不落盘**。密钥默认不写 localStorage。只有用户显式勾选「记住密钥」才存，且必须说明"换电脑就没有"。
2. **不进日志**。访问日志、错误日志、调试输出里都不能出现完整密钥。
3. **不进 prompt**。密钥只放 `Authorization` 头，绝不拼进 messages。
4. **进对话要提醒**。用户把 Key 贴进聊天记录时，必须提醒去后台轮换——聊天记录是持久化的。
5. **curl 导出要占位**。用户没填 Key 时，导出的 curl 里写 `$AIRBALL_API_KEY` 占位符，不要把空值或真值打进去。

## 项目内规范（airball 仓库）

上游 `BaseURL` 和 `APIKey` 只允许出现在 `gateway` 模块的配置和 provider 边界内。

- 不得进入前端、DTO、日志或任何普通业务模块
- 调用方不再携带上游密钥（走 gateway 代理）

这条来自仓库的 `AGENTS.md`，是架构级约束。

## 存储位置

| 场景 | 存哪 |
|---|---|
| 浏览器工具 | localStorage（仅勾选后），key 前缀 `i2p.apiKey` |
| 脚本 | 环境变量，如 `$IMAGE_API_KEY` |
| 项目内 | gateway 配置文件，不进版本库 |

## 检查清单

发布或提交前过一遍：

- [ ] 代码里没有硬编码的 Key
- [ ] 配置文件已在 `.gitignore` 里
- [ ] 日志输出不含 Authorization 头
- [ ] 错误信息不回显 Key
- [ ] 用户贴过的 Key 已提醒轮换
