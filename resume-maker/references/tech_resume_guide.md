# 技术简历写作指南

本指南帮助优化技术岗位简历的内容质量。

## 核心原则

### 1. STAR 法则

每条经历描述应包含：

- **S (Situation)** - 情境：项目/任务的背景
- **T (Task)** - 任务：你负责什么
- **A (Action)** - 行动：你具体做了什么
- **R (Result)** - 结果：取得了什么成果（量化）

**示例**：

```
一般描述：优化了网站性能

STAR 描述：面对首页加载慢导致用户流失的问题（S），负责前端性能优化（T），
通过代码分割、图片懒加载、CDN 部署等手段（A），将首屏加载时间从 3.2s 
降至 0.9s，用户跳出率降低 25%（R）。

简历精简版：主导前端性能优化，通过代码分割与懒加载将首屏时间从 3.2s 降至 0.9s，跳出率降低 25%
```

### 2. 动词开头

每条经历以强动词开头，避免"负责..."这种被动表述。

**技术岗常用动词**：

| 类别 | 动词 |
|------|------|
| 架构设计 | 设计、架构、规划、搭建、构建 |
| 开发实现 | 实现、开发、编写、封装、重构 |
| 优化改进 | 优化、改进、提升、降低、加速 |
| 问题解决 | 解决、修复、排查、定位、攻克 |
| 团队协作 | 主导、推动、协调、带领、指导 |
| 技术选型 | 引入、迁移、切换、升级、集成 |

**示例**：

```
差：负责公司后台系统的前端开发
好：使用 React + TypeScript 重构后台管理系统，开发 30+ 个业务页面
更好：主导后台系统技术栈升级，从 jQuery 迁移至 React + TypeScript，开发 30+ 页面，维护成本降低 40%
```

### 3. 量化成果

数字让成果更有说服力。

**可量化的维度**：

- 性能：响应时间、加载速度、吞吐量
- 规模：用户数、并发量、数据量
- 效率：开发周期缩短、人力节省
- 质量：Bug 率降低、测试覆盖率
- 业务：转化率、留存率、收入增长

**示例**：

```
差：提升了系统性能
好：优化 API 响应时间
更好：优化核心 API 响应时间，P99 延迟从 800ms 降至 120ms，QPS 从 500 提升至 2000

差：带团队做项目
好：带领 5 人团队完成电商平台开发
更好：带领 5 人团队，3 个月内完成电商平台从 0 到 1 开发，上线首月 GMV 达 200 万
```

### 4. 技术关键词

确保简历包含目标 JD 中的技术关键词，但要真实。

**关键词类型**：

- 编程语言：TypeScript, Python, Go, Java
- 框架：React, Vue, Spring Boot, Django
- 数据库：MySQL, PostgreSQL, Redis, MongoDB
- 工具：Docker, Kubernetes, Git, Jenkins
- 云服务：AWS, Azure, GCP, 阿里云

**注意**：
- 不要堆砌关键词
- 确保你真的用过该技术
- 可以写掌握程度：精通 / 熟练 / 掌握 / 了解

## 简历结构建议

### 技术岗推荐顺序

1. **基本信息** - 姓名、联系方式、GitHub/博客
2. **求职意向** - 目标岗位、期望城市
3. **技术能力** - 按类别列出技术栈
4. **工作经历** - 倒序，最近的在前
5. **项目经历** - 倒序，突出技术亮点
6. **教育背景** - 学校、专业、学历
7. **其他** - 开源贡献、技术博客、证书（可选）

### 篇幅建议

- 应届生：1 页
- 1-3 年：1-2 页
- 3-5 年：2 页
- 5 年+：2-3 页

### 每段经历的条目数

- 工作经历：3-5 条
- 项目经历：3-5 条职责 + 1-3 条成果

## 常见问题

### Q: 没有量化数据怎么办？

**A**: 尽量估算，或者用相对值：

```
无法精确测量：优化了数据库查询
可以估算：优化 10+ 个慢查询，平均响应时间降低约 50%
```

### Q: 项目是公司机密怎么办？

**A**: 描述技术方案，不透露业务细节：

```
不好：为 XX 银行开发风控系统，拦截了 1000 万欺诈交易
更好：开发实时风控系统，基于规则引擎和机器学习，日均处理 100 万笔交易，拦截率 99%
```

### Q: 技术栈太多怎么写？

**A**: 按熟练度分级，只列相关的：

```
推荐：
- 精通：React, TypeScript
- 熟练：Node.js, PostgreSQL
- 掌握：Docker, Redis

不推荐：列出 20 个技术但都不深入
```

### Q: 工作经历有空白期怎么办？

**A**: 
1. 如果有学习/开源/自由职业，可以写进去
2. 格式上只写年份，不写月份
3. 面试时准备好解释

## 针对不同岗位的建议

### 前端工程师

重点突出：
- 框架使用经验（React/Vue/Angular）
- 性能优化案例
- 组件封装/工程化能力
- 跨端经验（小程序、React Native）

### 后端工程师

重点突出：
- 系统架构设计
- 高并发/高可用经验
- 数据库优化
- 微服务/分布式经验

### 全栈工程师

重点突出：
- 端到端交付能力
- 前后端技术栈广度
- 独立项目经验
- 快速学习能力

### DevOps / SRE

重点突出：
- CI/CD 流水线建设
- 容器化/K8s 经验
- 监控告警体系
- 故障排查案例
