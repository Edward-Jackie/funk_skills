# 证据与新鲜度规范

CODEMAP 的价值全押在一件事上：**读它的人（同一个模型，下一次冷启动）能判断该信到什么程度。**
没有证据标签的地图不是地图，是猜测的集合 —— 而且比没有地图更危险，因为它看起来可信。

## 一、五级证据标签

关键结论后面必须挂一个标签。标签不是装饰，是**行动指令**：它告诉下一次会话「这条能不能直接动手」。

| 标签 | 含义 | 允许的动作 |
| --- | --- | --- |
| `source-verified` | 已核对源码中的显式调用、分支或状态写入 | 可作为实现事实动手 |
| `test-verified` | 相关自动化测试**已通过且覆盖该结论** | 可作为实现事实动手 |
| `runtime-verified` | 已在真实依赖或目标环境验证 | 可作为实现事实动手 |
| `unverified` | 证据不足，仅有命名或结构推断 | **只能当线索**，动手前必须核对 |
| `conflict` | 源码、测试、运行结果或人工规则互相矛盾 | **不得择一采信**，必须记入冲突台账 |

### 三条硬约束

1. **`test-verified` 不等于「这个文件有测试」。**
   必须是「跑过、通过、且这个测试确实覆盖了这条结论」三者同时成立。
   「有测试存在」不能自动推断「测试覆盖了这个结论」。

2. **`runtime-verified` 不能由读源码代替。**
   没在真实依赖上跑过，就写 `source-verified`。把运行盲区标成运行验证，是这份地图最贵的错误。

3. **从命名推断出的调用关系一律 `unverified`。**
   宁可标低，不可标高。一个被高估的证据标签，会让下一次会话直接跳过核对。

## 二、锚点格式

统一写 `文件路径 -> 符号名`，**绝不写行号**：

```
backend/common/services/identity/service.go -> finishLogin
```

行号是**派生值**：代码一移动它就失效，而且失效得**静默无声**（指向错误的位置但不报错）。
符号名稳定、可 grep、可校验，所以它才是锚点。需要跳转时用 `scripts/where.sh <文件> <符号>` 现算一个行号。
行号是查询结果，不是缓存数据。

## 三、新鲜度元数据

每个 CODEMAP 文件头部必须有：

```
<!-- codemap-meta
status: current
verified-at: 2026-09-16
verified-commit: 4dc017a
-->
```

`status` 取值与含义：

- `current` —— 核对过，可作为参考
- `needs-review` —— 首次迁移或大改后尚未回核
- `stale` —— 已确认落后于代码
- `conflict` —— 存在未决策的矛盾

**除 `current` 之外，其余状态只能当线索使用，不得作为实现事实。**
这是 `scripts/check_map.sh --strict` 的判定依据，也是 CI 拦住带病地图的依据。

## 四、条目级过期，而不是整文件过期

`check_map.sh` 比对 `verified-commit..HEAD` 时，**逐锚点报告受影响的文件**，而不是把整张地图标成废纸。

理由：半个文件过期和整个文件过期，应采取的动**完全不同**。
「整张图不可信」的结果是读的人干脆不用；「只有 billing 那两条要重核」的结果是其余照常可用。

过期是**降级**，不是死亡。脚本输出里明确写出「未列出的条目仍可继续使用」，就是为了保住这个降级。

## 五、冲突台账

业务规则和实现打架时，**不许替任何一方圆场**，两边都记：

```markdown
## 冲突台账

| 结论 | 声明方 | 实际实现 | 风险 | 待决策 |
| --- | --- | --- | --- | --- |
| 生成任务必须记录归属 | `human-confirmed`（需求文档） | `generation/client.go` 不写归属字段 | 越权查询、扣费纠纷无法追溯 | 谁负责补字段 |
```

规则：
- 冲突**不得被静默改写**成某一方的说法。
- 反向也成立：**不得因为实现如此，就把人工确认的规则删掉**。
- 冲突条目必须能被 `check_map.sh` 数出来，让它在每次校验里被看见。

## 六、人工保护块

人工写的陷阱、铁律、前置条件**无法从源码重新推导**，一旦被重扫覆盖就永久丢失。
这类内容必须包起来：

```
<!-- manual: keep — 人工撰写，禁止自动改写 -->
...
<!-- /manual -->
```

- 重扫时**逐字保留**保护块内容，只重建块外的自动生成段。
- 若发现人工内容**没被包住**，应当**把它包进去**，而不是让重扫把它冲掉。
- 宁可为一份又大又烂的地图做增量修改，也不要整文件覆盖。

## 七、与 git 的关系

地图**必须纳入版本控制**，与对应业务代码一起评审、一起回滚。
未纳入 Git 的地图在 `check_map.sh` 里报 [注意] 并在严格模式下失败 —— 因为一份没有历史的地图，无法判断它是什么时候、基于哪份代码写下的。
