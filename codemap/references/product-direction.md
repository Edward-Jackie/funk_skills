# 改造方向与分层契约

> 当前基线版本：**Codemap 3.1**（事实层沿用 Graph v2，渲染层为内置 Archify 3.2 分支）

Codemap 首先是 AI 的项目认知层，其次才是人的可视化入口。改造先冻结职责和信息流，再从源码生成地图；旧地图不能成为新版设计约束。

## 版本路线

改造顺序不可反：**先让地图不骗人，再让它更常命中，最后提升取数与讨论体验。**

| 版本 | 状态 | 范围 | 定调 |
|---|---|---|---|
| v3.0 | 已交付 | Markdown + Graph v2 + 内置 Archify 渲染、下钻外壳、`query_graph`、`impact_diff` | 当前基线；Explorer 已退役 |
| v3.1 | 进行中（①④ 已落地，② 部分） | ① 新鲜度守卫（过期分级、可失败、读取前警告）② 收益度量（M1 命中日志 / M4 过期比例）③ 页面级五层锚点 ④ MCP 只读取数层 | **只改校验、采集与取数层，不碰渲染链** |
| v3.2 | 未开工 | 画布批注图层、Overlay 三镜头渲染、viewer 补丁层扩展 | 讨论层；开工前须先验证侧车方案 U1 |

### v3.1 顺序（依赖关系，不可跳步）

1. **新鲜度守卫（前置，不可跳过）**：`verified_commit` 之外补"HEAD 领先多少提交/多少天"、锚点失效分级、`query_graph` 输出前置过期横幅。现状只有逐文件 `strict_warn`，不加 `--strict` 退出码仍为 0，等于不阻断。
2. **收益度量**：命中率、定位耗时、修图成本、过期比例只写本地 `.map/.metrics/`，不上报不阻塞。
3. **页面级锚点**：配置页/表单页记录 `route → View → Panel/组件 → API → service` 五层，复用 `path -> symbol` 锚点格式。投入大小由第 2 步数据决定，列表页与纯 CRUD 不建。
4. **MCP 只读取数层**：见下节边界。

### 已定调、尚未实现的（不得宣称已支持）

- 画布批注与 Overlay 三镜头图层：`build_views` / `compile_graph` 当前**没有** overlay 参数，页面上做不出任何涂层。
- 力导向发现图、提交钩子自动更新、`state`/`force` 布局。
- Graph 的 `rules` 字段已透传到侧车，但 `check_graph` 尚未校验它。

### MCP 边界（v3.1）

MCP 只包装同一套 Core，**只读、不写、不缓存第二份状态**：

- 工具：`codemap_list_projects`、`codemap_status`、`codemap_route`、`codemap_read`、`codemap_query`、`codemap_rules`、`codemap_impact`、`codemap_check`、`codemap_docs`。
- 每次响应必须携带新鲜度信封；`level` 非 `fresh` 时不得用确定语气给结论。
- 空命中必须给出原因，**不得被解读为"业务不存在"**。
- `codemap_read` 缺省返回章节目录，按 `heading` 精确读取；`codemap_check` 等价 `check_map.sh --age`。
- 写入工具默认不注册；只有设置 `CODEMAP_ENABLE_WRITE=1` 后才出现，仍须用户明确要求。
- 写地图、建图、`build_views` 等仍留在 skill 与 CLI，不进 MCP。

## 两类使用者

### AI 读取

AI 需要快速回答：任务改哪里、链路怎么走、哪些边界不能破、最小读取集是什么、结论有什么证据。

因此 `CODEMAP*.md` 优先保证：

- 从任务或故障现象到首个代码锚点不超过两跳。
- 只加载命中领域，不把全库文档塞进上下文。
- 高风险领域明确规则、不变量、状态真相、幂等、补偿和验证边界。
- 每个关键结论能回到源码、测试、运行证据或人工确认规则。

### 人查看

人需要快速发现：系统有哪些领域、一次业务如何跨模块运行、新需求影响哪些位置、当前看到的是事实还是方案。

因此 Web Explorer 优先保证：

- 全局关系图用于发现，局部关系图用于聚焦。
- 泳道图表达严格业务顺序，状态图表达生命周期。
- 点击节点查看业务解释、证据、Markdown 章节和源码锚点。
- Overlay 明确区分新增、修改、风险和移除候选。

人的交互状态不写回 Codemap。坐标、缩放、筛选、主题和展开状态都不是业务事实。

## 五层结构

```text
源码 / 测试 / 运行证据 / 人工规则
                ↓ 取证
CODEMAP*.md：AI 路由、边界、不变量、风险
                ↓ 提取关系语义
Graph v2：节点、边、泳道、条件、证据、上下文指针
                ├─→ Mermaid：静态嵌入
                ├─→ Web Explorer：交互探索
                ├─→ query_graph：任务到最小上下文
                └─→ impact_diff：代码改动到业务影响

Overlay：未实施需求 ──叠加──→ Web / query_graph
```

### 视图编译层

Graph 与 Overlay 通过可选 ViewSpec 进入类型化视图编译层，再交给当前 Explorer 或未来的 Archify 适配器：

```text
Graph / Overlay → ViewSpec → 临时 IR → HTML / SVG / 浏览器回执
```

- ViewSpec 只保存图 ID、语义类型、布局模式、焦点、过滤和质量上限，不复制事实。
- 临时 IR 可以包含渲染器需要的坐标、路由和行范围，但不得提交为 Graph 真源。
- Archify 是可替换渲染器，不是 Codemap 的业务规则层；MCP 只包装同一套 Core，不保存第三份状态。

- 源码、测试、运行结果和人工确认规则是事实证据。
- Markdown 是 AI 认知主入口，不为画图牺牲表达。
- Graph 是结构化关系层，不复制 Markdown 长文。
- Overlay 是方案层，不得伪装成当前实现。
- Mermaid、Web 和查询结果都是可丢弃、可重建的派生产物。

## Clean Break 重建

1. 冻结 Markdown 模板、Graph v2、Overlay 和工具行为。
2. 在隔离目录 `.map/next/` 选择一个真实高风险领域，从源码重新取证并生成完整样板。
3. 同时验收 AI 查询质量和人的可视化质量；不能只看页面是否好看。
4. 根据样板修正规范和工具，而不是迁就旧文件。
5. 用户确认后，按领域从源码批量重建；最后再决定是否替换 `.map/`。

旧 Graph 不兼容、不混读、不自动升级。旧 Markdown 只可用于发现可能遗漏的问题，任何结论都要重新取证。

## 验收标准

- AI：给出一个需求，能抽出有限节点、必要边界、最小 Markdown 章节和源码锚点。
- 人：能从整体进入领域，再切到单链路泳道；需求影响与当前事实视觉上明确分离。
- 可信度：`unverified`、`needs-review` 和 `conflict` 不会被界面包装成已确认事实。
- 一致性：修改事实只改 Markdown/Graph；所有视图重新生成，无第二套手写真相。
- 可维护性：新增需求只写 Overlay 或更新事实，不改渲染器、不手排坐标。
- 开发闭环：需求能正向定位代码，Git Diff 也能反向命中业务图、下游检查范围和未覆盖文件。
- 视图闭环：固定 ViewSpec 可以重建同一阅读镜头，且渲染器替换不改变节点、边、证据和业务条件。
