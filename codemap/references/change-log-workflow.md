# 共享日志、范围读取与维护闭环

适用于暴露 `codemap_log_search/read/timeline`、`codemap_budget`、`codemap_checkpoint` 的 MCP 服务。先看工具定义确认能力；旧服务缺少这些工具时明确说明，不能假称已记录。发布基线仍为 4.0，本节对应 v4.1 分支能力，不代表线上已升级。

## 事实与共享入口

- 云端 Codemap store 保存共享权威记录。Markdown/Graph 是地图事实，日期 JSONL 是变更历史；SQLite 仅为可重建索引，不手改、不入事实 Git、不跨设备同步数据库文件。
- 本机源码负责验证 HEAD、暂存/未暂存差异、未跟踪文件和显式配置依赖；云端无 checkout 时只能返回 `unknown`。
- 日志严格按 repo_id/branch 隔离。缺当前分支日志返回未初始化，不能沿用地图的默认分支回退，更不能继承来源分支的 applied。
- 云端同步失败明确报告。离线须显式选择本机草稿（MCP `CODEMAP_MODE=local`、CLI `--local`），不得静默切换权威入口。
- 日志 MCP 永远只读，旧地图写工具仍由本机显式开关控制；独立日志凭证按项目、分支授权，旧地图 token 不自动获得日志权限。没有授权不能改用匿名接口。

## 按需读取

理解任务 → 定位锚点 → 最小读取与核验 → 执行验证 → 按需维护地图。已知章节/对象直接读，不强制 status、目录、历史或 timeline 串行调用。

- 需要历史依据才 `search`，只取索引；已知 ID/section 直接 `read`，缺省只返回章节目录。`timeline` 仅用于先后关系不清。历史裁定用 `record_version` 或 `filters.history=true`，不当当前事实。
- `@revision/@anchors/@maps/@evidence/@decision` 是元信息章节；引用只定位，不自动读正文或递归展开。
- `codemap_docs` 缺省只给章节目录，已知 heading 直接读取；无标题文档使用 start_line/end_line，小文档整体核对须 whole=true 并提供 reason。resource 仅定位，不传正文。
- 新服务 `codemap_read` 对 Markdown 用 heading；对 Graph/Overlay 默认给对象目录，用 `selector="nodes/<id>"` 或 `edges/<id>/refs` 投影。旧 `max_lines` 不再永久截断正文。
- `next_cursor` 通过 `cursor` 取日志下一批/下一块；`page.cursor` 通过 `page_cursor` 续读同一工具结果。`encoding=json` 的 text 连续拼接后解析 JSON；查询范围或源版本变化须重新定位，不能沿用旧游标。

## 预算与委派

所有地图、日志及规范内容读取前用 `codemap_budget(action="begin",task_id=...,round_id=...)` 建轮；同任务的地图、日志和规范读取都传相同 task/round。默认每轮 32 KiB/8 次，单响应默认 4 KiB、硬限 12 KiB；索引默认 10 条、最多 20 条。预算不可在运行中自行放宽。

这些字节包括 MCP 文本结果外壳，不等于 token，不包含 JSON-RPC、工具定义或宿主继承上下文。旧工具也必须传轮标识；缺少时拒绝正文，不能切换旧入口绕过累计预算。资源 URI 只给定位，规范正文使用 codemap_docs 按章节读取。外部 shell/编辑器无法由服务拦截，宿主需如实记账；必读规则完整读完并单列开销。

委派仅服从宿主和用户规则；不要因为本节自动开启子 Agent。允许委派时，单领域短任务直接做，独立领域才分派只读任务：

1. 任务卡给原任务/轮次/尝试 ID、问题、允许路径或符号、版本证据、额度和停止条件，不复制整段会话。公共入口清单只取一次，按领域分配，交叉文件指定负责人。
2. 先留主 Agent 合并与检查点额度，再用 allocate 静态分配；额度不回收，新建尝试不能重置轮预算。报告目标 2 KiB、硬限 4 KiB，给结论、证据类型/等级、锚点、条件、版本、盲区及用量；索引不能冒充已核验报告。
3. 子 Agent 不写源码/地图/日志，不递归派生。超时先请求停止，确认终止并结算后才改派；无法确认就保持受阻。迟到结果归原尝试，不自动并入新裁定。
4. 主 Agent 复核高风险、跨域接缝和冲突。复用报告须核对实际文件及已知依赖，不能只看 HEAD。最终单点写入；报告转交用 report 计字节，外部读取调用仍由宿主轨迹计量。

耗尽返回带原任务/轮次/尝试的检查点定位；在原授权目标内显式 begin 新轮并传 parent_round_id，不能自动开轮遍历历史。在新轮用 codemap_checkpoint(source_task_id,source_round_id,source_attempt_id) 取已读范围/版本和 unread 续读参数，检查点正文也计新轮预算；page_cursor 续读外层 JSON，cursor 续读日志详情，不能混用。工具只证明读取范围，业务结论与盲区由宿主补充。宿主终止行为与真实单/双 Agent 效率仍需独立验收，服务静态额度测试不替代这些验收。

## 引用读取

已知锚点直接范围读取并核验版本；未知锚点先目录或关键词定位。文档按章节、源码按符号、配置按键/对象；大符号继续分块。只有任务确需整体核对的非日志小文件（同时不超过 4 KiB/120 行）可全文。日志、生成物、会话及批量 Diff 不适用小文件例外。失效锚点重新定位或标待审，不全文回退。完整审阅按范围覆盖并显式续轮，同版本同范围不重复灌入正文。

## 显式维护

实现唯一位于 MCP 服务仓，skill 不复制 JSONL/SQLite/预算实现。当前本机入口是 `~/dev/work/codemap/codemap_cli.py`；其他机器从已配置的服务安装目录定位，先读 `--help`，找不到应说明，不把此绝对路径当跨机器配置。

- 语义批次完成后 `record` 写 pending：填写行为变化、anchors、evidence、details；工具生成稳定 ID、operation_id、时间及源码指纹。优先级 P0/P1/P2 与影响 high/normal/low 分开。
- 根据 Diff、当前源码和地图裁定 add/update/delete/none；历史只在需要时查。源码删除可能更新替代路径；测试解除已有风险应更新 VERIFY，等价格式变化可 none。
- `apply` 先在隔离目录校验，保留 RULE/manual，再发布地图；源码/依赖及地图指纹匹配、门禁通过后才 applied。`skip` 留理由、核对范围和实际地图版本后 skipped；云端必须读取权威地图，地图凭证缺失或版本变化时不能关闭裁定。失败、版本变化或冲突保持/恢复 needs-review，不能提升整域新鲜度。
- 重试复用原操作 ID 和相同内容；新裁定另建操作。云端整文件删除用 deletes，服务维护分支删除标记，防止默认分支旧文件复活；历史 JSONL 不删除。
- 旧日志迁移默认预览，显式 apply 才写入；原始行保留，未知字段标待核对，不能伪造发生时间或继承旧完成状态。迁移真实数据、部署、推送均按当前任务授权边界执行。

## 渐进初始化

普通任务缺图先回源码；只有已授权初始化才写。区分分支缺图、项目全无图、旧图迁移。一次取入口清单，仅按任务和风险域取证；不指定任务时选择少量代表入口并声明范围，不把局部核验当全项目覆盖。

导航阶段用紧凑 L1/必要 L2 保存路由、锚点、局部调用线索和盲区，元信息标 `map-stage: navigation`；小项目可只建 L1。不创建空 Graph，不引用未生成视图。隔离草稿验过证据/链接/锚点/新鲜度后，先准备 L2 与 pending 日志，最后发布 L1；迁移保留旧图。源码变化只复核相关范围。

完整建图阶段将关系/条件/refs 归入 Graph，Markdown 保留导航和引用，不维护第二张关系表；标 `map-stage: graph`，运行 Graph、视图与浏览器完整门禁。存在 Graph 时即使标 navigation 也必须执行 Graph 检查。
