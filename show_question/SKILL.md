# 本地表单收集

用一个本地 HTML 页面收集比 `AskUserQuestion` 更丰富的结构化信息（开放文本、多选、滑块、矩阵、
下拉等），用户填完复制粘贴回来，我直接解析。全程不发一次网络请求，不需要发布到 claude.ai。

## 什么时候用这个，而不是 AskUserQuestion

- 问题超过 4 道，或需要开放式文本、多选、矩阵评分、下拉这类 `AskUserQuestion` 不支持的题型 → 用这个
- 4 道题以内、答案都是固定选项里选一个 → 直接用 `AskUserQuestion`，全自动回传，不用走表单这一套

## 第 0 步：先挖意图，再定收敛/扩散（硬规则）

**问卷为了什么目的、背后的真实意图，必须先挖清楚，且最终规模由用户拍板，不能 agent 自己膨胀
或收敛题目。** 顺序不能乱：

1. **意图挖掘（先问到底）**：主动追问，别浅尝辄止，例如——这个问卷最终要解决什么问题？给谁看？
   答完用来做决策还是做归档？有没有不能公开的敏感点？用户嘴上说的需求背后往往有更深的动机，
   挖到用户点头说"对，就是这个"为止。
2. **收敛/扩散（再定规模）**：用 `AskUserQuestion` 问用户要哪种粒度，三档默认：
   - **收敛**：只问最关键的 3~5 题，每道直击要害
   - **标准**：8~10 题，覆盖主要维度
   - **扩散**：10+ 题，全面铺开，多角度深挖
   用户选完，就严格按这个档位数出题，**不擅自加题、也不擅自砍题**。用户给自定义数量就按用户说的来。
3. **AI 自主性的边界**：在用户定好的方向和题量内，题目怎么设计（措辞、题型、选项、分组）由 agent
   **自主发挥**；但"问不问这个维度、问几道"这类收敛/发散决策，必须交给用户。省了这一步，出的题
   再多都不算数。

## 怎么做（配置化生成，推荐）

1. 按当前对话实际需求，新建一个 `config.json`（可参考本目录 `config.example.json`），用 JSON
   声明页面标题和题目。**题型、必填、分组、条件逻辑全在配置里，不用碰 HTML 和 JS。**
2. 跑 `python3 generate.py config.json`，自动生成同名 `.html` 文件。
3. 用 `open <path>` 直接在本地浏览器打开，不要用 Artifact 工具发布到官网（用户偏好本地模式）。
4. 提示用户填完点"一键复制 JSON"，粘贴回聊天框；"改成下载文件"是复制被浏览器拦截时的兜底选项。
5. 用户粘贴回来的内容就是一段 JSON 文本，直接解析，不需要额外确认。
6. **结果落盘存档（推荐）**：解析后把结果存进 `~/Desktop/问卷存档/`，方便后续追溯和汇总。
   用本目录的 `archive.py`：
   ```
   python3 archive.py "<问卷标题>" answer.json        # 先把 JSON 存成 answer.json 再跑
   echo "$json" | python3 archive.py "<问卷标题>"     # 或直接管道，不用落临时文件
   ```
   - 同名问卷多轮自动收进同一个文件，累计数组，每条带「建档批次」时间戳
   - 加 `--csv` 生成横表：`python3 archive.py "<问卷标题>" answer.json --csv`
   - 存档目录 `~/Desktop/问卷存档/`，多份归档后可用 `--csv` 汇总对比

### config.json 字段说明

```jsonc
{
  "title": "页面标题",
  "kicker": "顶部小标签（可选）",
  "dek": "给用户的一两句说明（可选）",
  "groups": [                       // 题组，可多个，空的可省略
    {
      "name": "组名",               // 可选，不写就不分组
      "fields": [
        { "key": "键名", "type": "text", "required": true, "placeholder": "提示" },
        { "key": "单选", "type": "radio", "options": ["A","B"], "other": true },
        { "key": "多选", "type": "checkbox", "options": ["甲","乙"] },
        { "key": "打分", "type": "range", "min": 1, "max": 10 },
        { "key": "城市", "type": "select", "options": ["北京","上海"] },
        { "key": "矩阵", "type": "matrix",
          "rows": ["界面","性能"], "cols": ["差","好"] },
        { "key": "带条件", "type": "textarea",
          "showWhen": [{ "key": "单选", "value": "A" }] }
      ]
    }
  ]
}
```

- **题型 `type`**：`text` / `textarea` / `radio` / `checkbox` / `range` / `select` / `matrix`
- **必填 `required`**：`true` 时未填完不能复制，实时高亮 + 顶部进度条
- **自由填 `other`**：仅 `radio`/`checkbox` 支持，加一个"其他"选项，用户可自填
- **条件逻辑 `showWhen`**：`[{key, value}]`，所选题 value 命中时才显示该题
- **分组**：`groups[].name` 分组，题多时按维度收纳

## 每个问题自带的能力（自动生成，无需配置）

- **跳过此题**：每题必备，勾选后该题键记为 `null` 并加一个 `《键名（跳过）》` 标记。
- **补充说明**：每题必备，可选文本框，非空才记，独立存为 `《键名（补充说明）》`。
- 解析时注意：`null`=跳过、`其他：xxx`=自己填、`《键名（补充说明）》`=附注，都不是缺数据，别误报。

## 已知的坑

- **改配置别改 HTML/JS**：`template.html` 是运行时引擎，`generate.py` 从配置装配。想加题型改
  `generate.py` 的 `fieldset_html()` 和 `template.html` 的 `collectAnswers()`，两边都要同步。
- **剪贴板 API 在 `file://` 页面不保证能用**：`template.html` 里已带 `execCommand('copy')` 兜底，
  不要动 `copyText()`。
- **条件逻辑和必填冲突**：被条件逻辑隐藏的题不参与必填校验和进度统计，避免"隐藏的必填题卡死"。
- **收敛/扩散是用户的事，不是 agent 的事**：第 0 步的意图挖掘和 `AskUserQuestion` 不能跳。agent
  想当然加题/砍题、或自己决定"这个维度不用问"，都算违规，重来一遍第 0 步。
- **不要用 `echo '<json>' | stdin` 这类方式往外传数据**：跟 JSON 无关，这条是历史教训，Bash 会把
  内联字符串里的 `\n` 转成真换行，凡是要落 JSON/多行内容到文件，用 Write 工具。
