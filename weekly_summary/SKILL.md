# Weekly Summary — 周报生成

根据当前会话历史记录，提取用户本周的开发工作，生成一份简洁的周报。

## 原则

1. **突出功能价值**：写"实现了什么能力"、"解决了什么问题"，而不是"改了哪些文件"
2. **业务成果导向**：强调对业务的影响，如"保障用户资金安全"、"提升服务可用性"
3. **去技术细节**：不写文件名、行号、函数名等实现细节
4. **结构清晰**：按功能模块分 1.2.3.4 条目，每条 2-3 句话
5. **简洁**：总字数控制在 300-500 字

## 格式

```markdown
# 周报

## 1. [功能模块名称]
- [一句话描述功能价值]
- [一句描述技术亮点或解决的问题]
- [如有，补充业务影响]

## 2. [功能模块名称]
...

## 3. [配套工作/其他]
- [文档、测试、设计文档等非功能类工作]
```

## 流程

1. 回顾当前会话中用户提出的所有开发需求
2. 按功能归类（如：路由系统、图片生成、语音服务等）
3. 每类提炼：做了什么 + 为什么做 + 带来了什么价值
4. 输出到用户指定的周报文件路径，或默认 `/Users/jack/dev/temp/weekly_summary.md`
5. 如果没有指定路径，询问用户想保存到哪里
