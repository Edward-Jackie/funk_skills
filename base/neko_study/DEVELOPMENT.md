# neko_study Skill 开发记录

> 创建日期: 2026-04-20
> 版本: v1.0

---

## 一、需求来源

用户希望创建一个个性化学习教练 Skill，用于系统掌握新技能或知识主题。

## 二、需求确认过程

### 初始需求

用户提供了一段完整的流程描述，包含 6 个阶段：确认主题 → 了解需求 → 构建大纲 → 制定路线 → 引导学习 → 持续支持。

### 细节确认（7 项决策）

| # | 问题 | 决定 |
|---|------|------|
| 1 | Skill 名称 | `neko_study` |
| 2 | 触发场景 | 用户说"我要学习XXX"、"我想学XXX"、"帮我学XXX"、"入门教程"、"系统学习"、"制定学习计划"、"怎么学XXX" |
| 3 | 用户画像 | 使用 Markdown 文件（`user_profile.md`），加载已有画像，每次学习后自动更新 |
| 4 | 资源推荐 | **不推荐外部资源**，基于自身知识体系定制学习方式和进度 |
| 5 | 大纲格式 | Markdown + checklist（`- [ ]` / `- [x]`） |
| 6 | 练习形式 | 先讲解 → 选择题 + 简答题，先让用户作答再给答案 |
| 7 | 进度记录 | 每完成阶段性学习就记录到对应主题文件中 |
| 8 | 学习风格 | 不用视频；用户意图驱动；理论推导和需求跟踪在对话中完成 |

### 文件结构确认

- 用户画像放在 Skill 主目录下：`user_profile.md`
- 学习记录按主题命名：`learning-records/{主题名}.md`
- 用户画像中包含 Mermaid graph 用于知识点关联
- 用户画像中记录已学习内容，方便后期加强

## 四、SKILL.md 核心设计

### 流程阶段

| 阶段 | 名称 | 核心动作 |
|------|------|----------|
| 0 | 确认主题 | 询问或提供 3 个选项 |
| 1 | 了解需求与加载画像 | 读取 user_profile.md，简短问答，创建记录文件 |
| 2 | 构建知识大纲 | 分三层（基础→进阶→应用），checklist 格式 |
| 3 | 制定学习路线 | 阶段、时长、里程碑、评估方式、预期产出 |
| 4 | 引导学习（核心循环） | 4a 讲解 → 4b 练习/讨论 → 4c 自测 → 4d 总结记录 |
| 5 | 持续支持 | 回顾进度、提示复盘、答疑、灵活调整 |
| 6 | 总结与深化 | 总体总结、后续路径、应用场景、更新画像和记录 |

### 核心原则

1. 每次只推进一步，等待用户回应
2. 语言清晰、鼓励式、不过度冗长
3. 用户意图驱动，不死板按大纲
4. 理论推导与需求跟踪在对话中完成
5. 不推荐外部资源

### 文件更新规范

- **user_profile.md**: 画像变化时、完成主题后更新，含 Mermaid 知识图谱
- **主题记录文件**: 大纲确认后、每阶段完成后、主题完成后更新

## 五、user_profile.md 字段设计

```markdown
- 基本信息（创建日期、最后更新）
- 学习偏好（风格、排斥方式、互动偏好）
- 已掌握技能列表
- 学习目标倾向
- 可投入时间（每日/每周）
- 知识图谱关联（Mermaid graph TD）
- 历史学习记录摘要（表格）
```

## 六、record-template.md 字段设计

```markdown
- 学习画像快照
- 知识大纲（三层 checklist）
- 阶段学习记录（讲解要点、自测成绩、用户反馈、薄弱点）
- 知识图谱（Mermaid）
- 总结与后续（总体总结、深化路径、应用场景）
```

## 七、后续优化方向（待办）

- [ ] **测试触发效果**: 用不同措辞测试 Skill 是否可靠触发
- [ ] **优化描述字段**: 根据实际触发情况调整 description
- [ ] **长主题处理**: 如果知识大纲很长，SKILL.md 接近 500 行限制，考虑拆分参考文件
- [ ] **多主题并行**: 当前设计假设一次学一个主题，是否需要支持同时学多个主题
- [ ] **画像文件路径**: 当前画像在 Skill 目录下，如果 Skill 安装在只读位置可能需要调整
- [ ] **自测题目生成质量**: 实际使用中检验选择题和简答题的质量，可能需要增加出题规范
- [ ] **薄弱点复习机制**: 当前只记录薄弱点，未明确何时安排复习，可考虑增加"复习提醒"逻辑
- [ ] **知识图谱自动更新**: 当前 Mermaid graph 需要手动维护，未来可考虑自动化
- [ ] **学习记录文件命名规范**: 中文主题名 vs 英文主题名的处理
